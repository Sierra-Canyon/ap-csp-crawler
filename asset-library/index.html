The 30-second version

  1. In Browse, click a picture or sound you like.
  2. Choose what it is for (player, wall, music…) and, if you want, only on level 4, that is your own level.
  3. Press Download. The file arrives already named correctly, for example wall4.png.
  4. Move it from your Downloads folder into the game's assets folder, the one that already has wall.png and player.png in it.
  5. Run the game again: cd dungeon-graphics then dotnet run -- 4. For the web player, drag the file onto the page instead.

That's the whole trick: the file's name is what tells the game where to use it. No code changes.

Good to know

Pictures can be any size

16×16, 32×32, a photo, the game squeezes it onto one tile. Use PNG with a see-through background for heroes, monsters, treasure and weapons.

Animation happens by itself

A picture that is wider than it is tall (32×16, 64×16) is read as a row of square frames and played as a loop. A picture that is four squares tall (32×64) is a walking sheet: the rows are facing down, left, right, up.

Undo

Delete the file you added. The game falls back to the plain one (wall.png), and if that is missing too it draws a colored block. Nothing you put in assets can break the game.

Using a tileset you downloaded

Free packs (for example the CC0 packs on kenney.nl) usually give you either a folder of single tiles or one big sheet.

Single tiles: copy the one you want into assets and rename it, e.g. tile_0040.png → wall4.png.

One big sheet: copy the sheet into assets and add lines to assets/assets.txt saying which square is which. Count squares from 0, starting at the top-left:

wall4   = tilemap_packed.png  size 16  col 4  row 3
floor4  = tilemap_packed.png  size 16  col 0  row 4
# if the sheet has 1-pixel gaps between squares:
wall4   = tilemap.png  size 16  gap 1  col 4  row 3

Only use art and music you made, or that the creator says is free to use, and credit them in your README.
